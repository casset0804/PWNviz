# PWNviz 国际化（i18n）

PWNviz 面向中国 CTF 初学者，**默认界面是简体中文**，同时提供完整英文界面。
切换语言不需要刷新页面，选择保存在 `localStorage` 的 `pwnviz.locale`。

> 真实性原则同样适用于语言：翻译的是**界面**，不是数据。寄存器名、指令、变量名、
> 符号、地址、十六进制字节和 GDB 原始输出保持原样。

---

## 1. 约定

| 项 | 值 |
|---|---|
| 默认语言 | `zh-CN` |
| 支持语言 | `zh-CN`、`en-US` |
| 存储键 | `pwnviz.locale` |
| 库 | `i18next` + `react-i18next` |
| 命名空间 | `common`、`toolbar`、`panels`、`debugger`、`errors`、`settings`、`explanation` |
| 缺省命名空间 | `common` |
| 回退语言 | `zh-CN` |
| HTML 标记 | `document.documentElement.lang` 与 `data-locale` 同步更新 |

首次打开（或存储不可用）时一律显示简体中文；只有用户主动切换或显式保存过
`en-US` 时才显示英文。

## 2. 目录

```text
frontend/src/i18n/
├── index.ts                 # 初始化、切换、持久化、非组件翻译
└── locales/
    ├── zh-CN/
    │   ├── common.json      # 通用词、语言名、行数/字节数
    │   ├── toolbar.json     # 工具栏按钮、标题、连接状态
    │   ├── panels.json      # 面板标题/提示/空状态/环境变量/变量面板
    │   ├── debugger.json    # 状态栏、日志事件
    │   ├── errors.json      # 前端错误与后端错误码映射
    │   ├── settings.json    # 语言/动效/性能开关
    │   └── explanation.json # 逐条指令解释的标题/句子/事实
    └── en-US/               # 与 zh-CN 完全相同的键集合
```

`frontend/src/i18n/i18n.test.ts` 会逐个命名空间比较两种语言的**键集合**，任何缺失
或多余的键都会让测试失败。

## 3. 使用方式

组件：

```tsx
const { t } = useTranslation(["panels", "common"]);
<h2>{t("panels:stack.title")}</h2>
```

非组件代码（store、日志、错误包装、hooks）：

```ts
import { translate } from "../i18n";
translate("log.launching", { sessionId }, "debugger");
```

语言切换组件是 `frontend/src/components/common/LanguageSwitch.tsx`，位于 Toolbar
右上方，选项文字始终以各自语言显示（`简体中文` / `English`），
`data-testid="language-switch"`。

切换实现：

```ts
await setLocale("en-US"); // 写入 localStorage + 更新 <html lang> + i18n.changeLanguage
```

react-i18next 的订阅会让所有使用 `useTranslation` 的组件重新渲染，因此
**整个工作台立即更新，无需刷新**。React `memo` 不会阻止语言切换，因为
`useTranslation` 的订阅在组件内部。

## 4. 哪些内容不翻译

保持原文（技术事实）：

- 寄存器名：`RIP` / `RSP` / `RBP` / `RAX` …；
- 汇编助记符与操作数：`push` / `pop` / `mov` / `ret` / `call` …；
- 变量名、函数符号、结构体/类型名（DWARF 原样）；
- 内存地址与十六进制内容；
- GDB/MI 原始输出、错误原文、停止原因（如 `end-stepping-range`）；
- 原始 ELF 文件名与样例 ID；
- 变量来源字段值 `dwarf` / `debug-info` / `gdb-memory`（用于审计与测试断言）。

翻译的是解释性文字，例如：

| 英文 | 中文 |
|---|---|
| Stack memory | 栈内存 |
| Instruction pointer (RIP) | 指令指针（RIP） |
| pc / sp | 程序计数器 / 栈指针 |
| breakpoint hit | 断点命中 |
| optimized out | 已优化掉 |

寄存器名出现在句子中时保持大写原样，例如
`将栈内存定位到 RSP 0x00007fffffffe210`。

## 5. 后端错误：稳定 code + params

后端 `PwnvizError` 现在携带可选的 `params`：

```json
{
  "error": {
    "code": "invalid_session_state",
    "message": "Session is RUNNING; this action requires STOPPED.",
    "params": { "state": "RUNNING", "required": "STOPPED" }
  }
}
```

前端 `ApiError` 解析 `code` 与 `params`，`debugStore.errorMessage()` 通过
`errors` 命名空间翻译成当前语言；未知 code 直接显示后端原文。

| code | 前端 i18n key |
|---|---|
| `backend_unreachable` | `errors:backendUnreachable` |
| `invalid_request` | `errors:invalidRequest` |
| `invalid_session_state` | `errors:invalidSessionState` |
| `session_closed` | `errors:sessionClosed` |
| `too_many_sessions` | `errors:tooManySessions` |
| `sample_not_found` | `errors:sampleNotFound` |
| `sample_not_built` | `errors:sampleNotBuilt` |
| `debugger_unavailable` | `errors:debuggerUnavailable` |
| `debugger_timeout` | `errors:debuggerTimeout` |
| `debugger_error` | `errors:debuggerError` |
| `cross_site_blocked` | `errors:crossSiteBlocked` |
| `internal_error` | `errors:internalError` |

`debugger_error` / `debugger_timeout` 的译文包含 `{{message}}`，把 GDB 原文附加在
译文之后，**底层调试信息不会丢失**。

尚未结构化的是 GDB 自己返回的文本（`-data-disassemble` 失败等）：这些按设计保留
原文。

## 6. 指令解释的翻译

`frontend/src/lib/explain.ts` 返回 `StepExplanation`（headline / lines / facts）。
它接受一个可注入的翻译函数：

```ts
explainStep(previous, current, lastAction, (key, params) => t(key, params))
```

- 默认参数使用 `zh-CN/explanation.json` 构建的翻译器，因此单元测试和日志里的
  默认输出仍是中文；
- 面板传入 i18next 的 `t`，英文界面得到英文解释；
- 事实行（`RIP a → b`、`RSP a → b (delta)`）在两种语言中保持寄存器名与地址不变。

## 7. 测试

```bash
cd frontend
npm test          # 含 i18n key 对齐、切换、持久化、技术标识符用例
```

`src/i18n/i18n.test.ts` 覆盖：

- 没有存储时默认 `zh-CN`；
- 使用 `pwnviz.locale` 并拒绝非法值；
- 切换后立即生效且可切回；
- 两种语言的键集合完全一致；
- 没有空翻译、没有泄漏成 key 的翻译；
- 技术标识符不被改写。

`src/lib/explain.test.ts` 额外验证同一份测量结果在 `en-US` 下生成英文解释，
同时保留地址与寄存器名。

端到端（真实浏览器 + 真实 GDB）在 `scripts/ui_smoke.mjs` 中验证：

1. 清空存储后首次加载为 `zh-CN`，状态栏显示「空闲」；
2. 通过语言下拉切换到 `en-US`，`<html lang>` 与界面文字立即变化；
3. `localStorage.pwnviz.locale === "en-US"`；
4. 运行完整调试流程（英文界面）；
5. 切回 `zh-CN` 并刷新页面，语言与界面保持中文。

## 8. 覆盖范围

已翻译（两种语言）：

- Toolbar 全部按钮、标题、连接状态、语言开关；
- StatusBar 状态、动作、断点、快照、事件流、性能摘要 tooltip；
- Disassembly 面板（含空状态、列标记 tooltip）；
- Stack Memory 画布（图例、列头、HIGH/LOW、RSP/RBP 越界提示、不可读提示、
  byte tooltip 与 aria-label）；
- RegisterPanel（分组、状态、before/after 提示）；
- VariablesPanel（无快照/无 DWARF/空帧/延迟/缓存状态、刷新按钮、location kind、
  provenance、指针目标、aria-label）；
- MemoryInspector（选中字节、pointer target、qword/ASCII、diff、越界提示）；
- DiffPanel、ExplanationPanel、DebugLogPanel、EnvironmentPanel、BottomDock；
- 所有空状态、加载状态、tooltip、aria-label、按钮 title；
- 面板折叠/展开提示、错误横幅、dismiss 按钮；
- 前端错误（网络不可达、HTTP 失败、store 包装错误）；
- 指令解释的标题与句子；
- 语言/动效/性能相关的设置文案。

刻意保留英文/原文：寄存器、指令、变量、符号、地址、字节、GDB 输出、样例 ID。
